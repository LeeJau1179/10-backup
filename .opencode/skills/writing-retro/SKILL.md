# 写后复盘与语料库迭代（writing-retro）

本技能服务两件事：
1. **留存初稿基线**：写完初稿时顺手保存一份快照，防止对话拉长或文件被覆写后丢失初稿原件。
2. **修改复盘与归并迭代**：作者改完正文后，对比「本轮初稿」与「修改后正文」，追问大改原因，**先检索归并、不盲目新增**，并将累计命中 ≥ 3 场的高频问题自动升入《AI 语录》顶部的【🔴 高频红线】区。

> 本技能不依赖 Git 历史，也不要求作者手动贴两版文本；默认直接从当前对话和硬盘文件取数。

---

## 用法一：写完初稿时保存基线快照

当你在对话中刚写出某场初稿（无论输出在对话还是写入场景文件）时，执行一次快照保存：

```powershell
python .agents/skills/writing-retro/scripts/retro_ledger.py snapshot --scene "<场次名，如 02-100 中午会合·行程照旧>" --file "<场景文件路径>"
```

若初稿仅在对话中尚未落盘，通过 stdin 传入初稿正文保存：

```powershell
@'
<初稿正文>
'@ | python .agents/skills/writing-retro/scripts/retro_ledger.py snapshot --scene "<场次名>" --stdin
```

快照存在 `.writing-retro/snapshots/`（已 gitignore，Obsidian 不索引，复盘完成后自动清理；台账在 `.writing-retro/state.json`，均在沙盒可写目录内）。

---

## 用法二：作者改完稿后运行复盘

### Step 1：获取「初稿」与「改后正文」（不走 Git）

- **初稿来源**（按优先级）：
  1. 本轮对话中刚写出的初稿文本；
  2. 保底快照 `.writing-retro/snapshots/<场次名>.md`；
  3. 作者在对话里直接给出的初稿片段。
- **改后正文来源**：
  1. 硬盘上当前场景 `.md` 文件（去除 YAML frontmatter 只比对正文，同时读取 frontmatter 与对应 `SceneNotes` 作为背景参照）；
  2. 作者在对话里直接提供的修改后段落。

### Step 2：对比差异并按改因分流（严禁一刀切跳过大改）

逐段列出实质修改，结合你们开写前在对话中商定的**初稿方向**，将修改分成三类：

1. **明确写作问题**：如过度解释、空镜头暗示、虚指、流水账、人物信息差错误、常识错误、闪回断层、对话断头、群体硬加表情、刻意旁白，或违背《写作风格》与场景边界。
2. **疑为剧情/设定大改（必须追问定夺，不可默认排除）**：
   - 先分析是否属于以下可沉淀问题：**初稿写塌/逻辑卡壳/动机不足迫使作者重写救场**、**漏用前置设定导致补漏洞**、**AI 擅自加设定偏离商定方向**、**连续多次出现的同向审美改写**；
   - 只要无法百分之百确定是“纯单次换灵感”，一律标记为 **`待裁定`**，在确认表里列出并在表下追问作者一句：*“这段大幅改动，是因为初稿写塌/卡壳被迫重写（记入技法问题），还是单纯临时换了剧情点子（单场变道跳过）？”*
3. **纯单次内容变道**（作者确认只是临时换个时间/道具/念头，且原稿写法本身没毛病）：标为跳过，不入规则库。

### Step 3：检索现有台账，强制「先归并、后微调、极少新增」

先执行以下命令查看全部现有条目（同步对照 `StoryLine/逆世书/今生/Notes/AI 语录.md` 是否有作者近期手改措辞）：

```powershell
python .agents/skills/writing-retro/scripts/retro_ledger.py list
```

对每一条确认要入库的问题，严格按顺序匹配：

1. **命中已有条目**：**禁止新增**。记入该 `id`（计数按场景去重 `+1`）。
2. **已有条目的新变体 / 原则需要收紧**：仍归入该 `id`，同步提炼更新 `principles` 或替换 1 个更凝练的 `typical` 反例（单条保持精练，避免越堆越长）。
3. **全新根因**（现有全部条目均无法覆盖其核心毛病）：才提议写入 `new_items`，初始进入【🟡 观察区】（命中 1 场）。

> **绝对禁止**：不要自我辩护；不要为同一根因按不同具体场景起多个新条目（例如不能把“喝茶时扫视茶具”和“进教室时扫视黑板”建两条，必须合并进 `P04 流水账和填充动作`）。

### Step 4：输出「复盘确认表」等待作者拍板

**落盘前必须先输出确认表**，经作者确认后再写库：

| 修改片段 / 位置 | 初稿方向 vs 改动摘要 | 判定归类 | 拟执行动作 |
| --- | --- | --- | --- |
| 第 X 段 | 原稿… → 改为… | 命中 `Pxx` / 拟新增 / 待裁定 | 计数 +1 / 补充原则：… / 追问改因 |

若有「待裁定」的大改段落，在表格下方集中列出 1～2 条简短追问，由作者直接拍板算入库还是跳过。

### Step 5：作者确认后落盘并重算红线

作者确认（及裁定完大改项）后，构造更新 JSON（UTF-8）通过脚本执行落盘（也可用 `--json-file <tmp.json>` 传参，跨 PowerShell/bash 通用）：

```powershell
@'
{
  "scene": "02-100 中午会合·行程照旧",
  "hits": [
    {
      "id": "P04",
      "title": null,
      "typical": null,
      "principles": null
    }
  ],
  "new_items": [],
  "cleanup_snapshot": true
}
'@ | python .agents/skills/writing-retro/scripts/retro_ledger.py apply --stdin
```

**字段说明**：
- `hits[].title` / `typical` / `principles`：不需要修改原规则时填 `null`；需要微调时传完整最新文本/数组（若作者之前手改过 `AI 语录.md`，务必先把作者的措辞合并进来）。
- `apply` 会自动：
  - 按 `scene` 去重统计命中场次（同一场反复复盘不重复 +1）；
  - 将累计命中 `≥ 3` 场的条目升入 **🔴 高频红线**，并维持红线区最多 `8` 条（超出时按命中场次与最近活跃度保留 Top 8）；
  - 重新渲染干净的 `StoryLine/逆世书/今生/Notes/AI 语录.md`（严格不留日期和修订流水账）；
  - 清理该场临时快照。

### Step 6：结果汇报与强提示

落盘后，若 `promoted_to_redline` 非空，**必须在回复最开头显眼提示**：
`🚨 新晋升高频红线：[红线｜命中 N 场] <标题>`；并列出本次 `demoted_to_watch`（如有）及更新后的有效红线数。
