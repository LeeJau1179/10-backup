# aiout：《逆世书》改稿流程

目标：让正文像这本书、这个人物、这一刻，而不是符合某种通用的“反 AI 文风”。不设通用禁词表，判断以本书文风和作者认可的写法为准。

## 开工前必读

按顺序读，没读完不动笔：

1. `StoryLine/逆世书/AGENTS.md`：写作注意事项、链接铁律、冲突判定。
2. `StoryLine/逆世书/今生/Notes/写作风格.md`：文风规范、量化指纹、参考片段。
3. `StoryLine/逆世书/今生/Notes/AI 语录.md`：案例库（原文 → 改法 → 规则）和写作问题。
4. 目标场景卡（`synopsis`、`conflict`、`setup_scenes`／`payoff_scenes`）、它的 SceneNotes（节拍、边界）与正文，以及前后各一场正文。
5. 场景涉及的人物、地点、设定的 Codex 词条（身份、知情范围、硬规则）。

参考片段和 [[生日谎言·老周递烟]] 至 [[宿舍初熟·四人到齐]] 这批场景是作者认可的写法基线。基线里出现过的写法，不当 AI 腔处理。

## 四种模式

| 模式 | 做什么 | 不做什么 | 触发 |
| --- | --- | --- | --- |
| 检测 | 出问题表 | 不改任何文件 | 检查、看看、审一下、有没有 AI 味 |
| 清理 | 删、压缩、局部改句 | 不加心理、不加情节、不改动机和事件顺序 | 去 AI 味、清理、润色 |
| 重写 | 按作者说明重写点名的场景或段落 | 不动没点名的部分 | 重写、改这场 + 作者说明 |
| 新写 | 按场景卡和 SceneNotes 写正文 | 不越过场景卡的事件边界 | 写这场 |

判断不出模式时按检测处理。

## 闸门

- 检测以外的模式，先复述理解：这场要完成什么、作者的说明怎么理解。作者确认后再动笔。作者最新的说法优先于旧大纲。
- 清理模式先出问题表，作者选定改哪几条，再落盘。
- 作者的解释和纠正只用来理解意图，不写进正文。
- 只改作者点名的场景。其他场景发现的问题只报告。
- 正文与场景卡、SceneNotes 冲突，以场景卡和 SceneNotes 为准；作者也会手改正文，所以复述时逐条列出冲突（卡或笔记写什么、正文写什么），作者确认后再改。正文与 Codex 冲突，Codex 为准。
- 预计改动超过该场三成，停下说明理由，问是否转重写。
- 疑似伏笔、人物声音、作者有意的写法，标「待作者定」，不改。

## 检查顺序

按 [references/checklist.md](references/checklist.md) 逐层检查：

1. 剧情与现实逻辑
2. 人物行为与对白
3. 连续性（时间、地点、身份、谁知道什么）
4. 叙述与情绪
5. 措辞

前三层的问题先处理，再看后两层。能删就删，删不了再改写，最后才换词。

## 分级

每条问题归入一级：

- **明确问题**：原文证据足以确认，例如人物知道不该知道的事、常识错误、前后矛盾。
- **阅读风险**：有依据但取决于上下文，例如解释可能压住动作、暗示读者可能读不出。
- **偏好**：不影响理解、人物和节奏的表达选择。只轻量提出。

“像 AI”本身不是证据。每条必须给出原文短引，并说明读者会因此失去什么（信息、画面、人物感、节奏、理解）。

## 输出

格式见 [references/report.md](references/report.md)。提到场景时写标题加一句剧情，不只写编号。

## 落盘

- 直接改正文，不写修订记录、日期、来源标注。
- 人物名一律用 wikilink；不改 frontmatter。
- 改完回读该段前后文，确认事实、视角、语气、衔接没被破坏；报告实际改动的位置，检查过但没改的段落单独说明。

## 回流

作者在 AI 稿基础上改完后：

1. 用 git diff 对比 AI 稿和作者终版，找出作者改了什么。
2. 每处有代表性的改动，整理成一条案例：原文 → 改法 → 规则。改法以正文现行版本为准，不取中间某次提交的文字；同一处作者改过多轮时，以最后一版为准。
3. 作者确认后，追加到 `AI 语录.md` 的“需修饰举例”对应小节。
4. 同类问题第二次出现，再到“写作问题”里补或新增修改原则。一次性的要求不记。
